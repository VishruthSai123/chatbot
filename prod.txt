### B. What Vercel Chatbot Already Gives Us

We can directly reuse over **60% of the foundational infrastructure**:

1. **Authentication & User Isolation:**
   - Pre-configured NextAuth with anonymous guest sessions and user accounts.
   - Multi-tenant data isolation (`userId` checks across chats and documents).
2. **Two-Pane Workspace Layout:**
   - Framer-motion responsive split pane with drawer behavior on mobile and side-by-side dock on desktop.
   - SWR cache hydration and synchronized state across windows.
3. **Resumable Streaming Engine:**
   - `@ai-sdk/react` + `resumable-stream` with server-sent event (SSE) recovery across network disconnects.
4. **Interactive Action Rendering:**
   - Built-in UI components for step-by-step tool execution badges, collapsible reasoning traces, and error toasts.
5. **Database ORM & Migrations:**
   - Drizzle ORM setup with clean migration scripts (`lib/db/migrate.ts`) ready to accept testing schemas.

### C. What We Need to Add

1. **Project & Target Configuration Layer:**
   - Ability to define an application under test: Target URL (production, staging, preview, local), default viewport, authentication credentials for the target app, and browser flags.
2. **Browser Use Cloud Execution Layer:**
   - Service client to spawn, manage, and reuse persistent Browser Use sessions.
   - Extraction of the live WebSocket/WebRTC VNC stream URL (`session.liveUrl`) and session recording URLs.
3. **Right-Hand "Live Reality" Preview Pane:**
   - Interactive iframe/VNC live browser view replacing the text/code editors.
   - Action timeline overlaid on top of the live viewport showing real-time agent actions (clicks, inputs, navigations).
4. **Product QA Orchestrator (Testing Engine):**
   - A specialized reasoning layer that converts user intents ("Test checkout", "Try invalid credentials") into a structured QA Test Plan (Hypothesis, Steps, Assertions).
   - Evaluation agent that checks DOM state, network responses, and console logs to yield a verified verdict: `PASS`, `FAIL`, or `UNCERTAIN`.
5. **Structured Evidence & Finding System:**
   - Automatic capture of reproduction steps, network failures, console errors, DOM snippets, before/after screenshots, and video replay links.
   - Exportable Bug Report / QA Finding cards.
6. **Session-Level Browser Continuity:**
   - Maintaining browser session state across consecutive chat turns (e.g., Turn 1 logs in; Turn 2 tests settings as that logged-in user without re-authenticating).

### D. What We Should NOT Build

To avoid scope creep and deliver a high-velocity V1:

* ❌ **Do NOT build a browser automation engine from scratch.** (No raw Playwright/Puppeteer orchestration servers; rely strictly on Browser Use).
* ❌ **Do NOT build an autonomous code-generation/PR engine in V1.** (Do not edit customer codebases or execute automated code fixes).
* ❌ **Do NOT clone customer Git repositories.** (No local repo checkouts, AST parsing, or CI runners).
* ❌ **Do NOT build a complex multi-agent framework** (No swarm frameworks, AutoGen, or LangGraph abstractions).
* ❌ **Do NOT build a synthetic persona simulation engine.**
* ❌ **Do NOT build custom billing or usage meters in V1.**

#### Architectural Separation of Concerns:
1. **Browser Execution Layer (Browser Use):** Does the low-level heavy lifting (clicks, keypresses, scrolls, tab management, cookies, screenshots, video encoding).
2. **QA Intelligence Layer (Our System):** Interprets testing goals, generates test assertions, inspects output diagnostics, validates expected vs. actual results, and determines bug severity.
3. **Workspace Presentation Layer (Next.js):** Coordinates live visual feedback, streaming progress ticks, and evidence review.

### G. Browser Use Integration Strategy

1. **Session Lifecycle:**
   - When a test begins or a target URL is provided, call `client.sessions.create({ keepAlive: true })` via Browser Use SDK.
   - Obtain `session.id` and `session.liveUrl`.
   - Store `sessionId` in the session context (`TestSession` record) so follow-up chat messages reuse the same browser state, cookies, and page tab.
2. **Live View Streaming to Right Pane:**
   - The right pane renders an iframe embedding `session.liveUrl`.
   - The user watches the agent interact with their actual web app in real time with low latency.
3. **Execution & Event Streaming to Chat:**
   - Execute actions on the session.
   - Stream incremental status events (`data-qa-step`: "Clicked checkout button", "Entered coupon code") to the AI SDK data stream writer, displaying animated checkmarks in the chat.
4. **Recording & Teardown:**
   - When the session finishes or the test evaluates, fetch session recordings and snapshots via `client.sessions.files(sessionId)`.

```
                     │                             │
                     ▼                             ▼

       │ (Fetch /api/auth handler) │    │ architecture cause │
       └─────────────┬─────────────┘    └────────────────────┘
                     ▼
       ┌───────────────────────────┐
       │ Explain code cause        │
       │ + draft GitHub Issue      │
       └───────────────────────────┘
```

1. **Strictly Non-Intrusive:**  
   GitHub is only queried **after** a failure is identified to enrich the finding with code context (e.g., matching a failed API route or frontend selector to a file in the repo via the GitHub REST API).
2. **No Local Cloning:**  
   Never clone the repo on the server. Read specific tree paths via GitHub Octokit / Contents API using user OAuth tokens.
3. **Safe Progressive Action:**  
   Provide a "Create GitHub Issue" button pre-filled with Markdown reproduction steps, screenshots, and logs.

### K. Major Technical Risks & Mitigations

| Risk | Impact | Mitigation Strategy |
|---|---|---|
| **Iframe / Embedding Restrictions (`X-Frame-Options` / CSP)** | Live preview fails to embed in iframe | Browser Use `liveUrl` is served from Browser Use's domain (`live.browser-use.com`) which renders a streaming canvas/VNC stream, bypassing target app CSP headers completely. |
| **Session Inactivity Timeout** | Long LLM reasoning steps cause the browser session to shut down | Pass `keepAlive: true` and send periodic lightweight health-ping action checks to maintain session warmth during reasoning. |
| **Test Hallucination (False Passes)** | Agent assumes an action succeeded without verifying DOM | Require explicit two-phase verification: Action Phase (`click`) followed by Assertion Phase (`verify URL / element change`). |
| **Vercel Serverless Function Timeouts (60s cap)** | Multi-step browser tests take 90s–180s | Delegate long-running execution to background jobs or stream continuous SSE progress packets through Next.js streaming API routes to prevent gateway timeouts. |
